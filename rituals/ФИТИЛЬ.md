# РИТУАЛ ФИТИЛЬ (Приказ №6 — ключ живёт дольше спички, а не дольше империи)

## Факт, из-за которого ритуал существует

За трое суток (16.11 и 19.11) в чатах погибли **два** классических мастер-ключа
с максимальными скоупами (`repo, delete_repo, admin:org, workflow, audit_log…`).
Этим ключом вселенная стирается одним вызовом API. Классический PAT не умеет
отзывать сам себя — кремирует только Хозяин. Мир: fine-grained токены,
least privilege, короткий срок жизни, секрет-хранилище. Мир прав — и этого мало.

## Периодичность

Постоянно. Пересмотр реестра ключей — при каждой смене и каждой СВЕРКЕ.

## Процедура

1. **Тонкий ключ** — только fine-grained: read-only, скоуп = конкретные репо,
   дата смерти ≤ 90 дней (а лучше = длительность одной смены). Ключ — сменный
   пропуск, не паспорт.
2. **Хранение** — секрет-хранилище или env раннера (`secrets.*` в Actions).
   Никогда: чат, артефакт, код, README, скриншот.
3. **Публичное появление = немедленная кремация.** Не «пересоздам потом» —
   Delete сейчас, затем audit_log на чужие вызовы между публикацией и отзывом.
4. **Ключ с delete_repo / admin:\*** живёт только в сейфе и только на время
   переворота. После переворота — в утиль в тот же час.
5. **Реестр ключей** `karta/keys/README.md`: имя, скоуп, дата смерти, владелец.
   Ключ вне реестра = нелегал, кремируется при обнаружении.

## Критерий успеха

- `grep -r "ghp_" чат-логи` = 0;
- ФЕНС зелёный на всей истории;
- ни один живой ключ не старше 90 дней и не шире read-only без причины.

## Правило честности

Утечка ключа — не позор, а данные. Сокрытие утечки — позор.
Оба ключа 16.11 и 19.11 вписаны в кремационный список ФЕНСА как шрамы:
история помнит раны не для стыда, а для иммунитета.
